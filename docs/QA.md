# 品質検証・判定基準

## 2026-11-03：デッドゾーン型カメラのA/B試遊（Issue #104）

- `/` は従来追従、`/?camera=deadzone` は独立したデッドゾーン追従。URL以外に主要操作が変わらず、比較切替は手引きの押しやすいリンクから可能であること。ページ再読込・一時的な現在地の非継承を手引きに明示する。
- 新方式の2マス以内の徒歩では背景のカメラ位置が変わらない。約2.45マスの不感帯を越えてからの長距離徒歩では、左右上下の進行方向に余白が育つ。画面縦390×740/320×568、横844×390、5.7/7.35タイル/秒、30/60/120Hz、0.8/0.46/0.38倍率で測る。
- 前方へ手動パンした構図を勝手に戻さない。曲がり角・方向反転・停止時のリセンター・画面外れ・世界境界・タップ停止・NPC/施設/地図/会話を回帰する。旧 `?atlas=previous`、classic、prototype は既存方式。
- この比較試作に固定室内カメラ・ゼルダ型画面切替は存在しない。実機Safariの自然さや旅情の優劣は**自動テストでは決定できない**ため人間が試遊して判断する。


## 2026-11-02 夜：前方カメラの穏やかな追従（Issue #101）

- プロデューサーの「ぐいっと動きすぎ」を受け、先読み目標は残しながら、2.6マス後の追従立上りを**5マスのsmoothstep**へ変更（最初の6マス試用は実画面で前方視界が育つのが遅すぎると判定されたため調整）。フレームごとのカメラ速度を抑える。
- iPhone相当の縦390×740/320×568、横844×390、左右上下の移動で、2マスの静止構図、4〜8マス間の緩やかな追い上げ、10〜16マス後の自然な先読みを確認。現地5.7/地図7.35の双方を比較し、**同じ歩数後の構図の差が大きくならない**ことを必須の回帰条件とする。
- Nodeの30/60/120fps再生や0.8/.46/.38倍率、手動で先へパンした後の非逆行、世界境界/主人公可視、曲がり角を回帰。既存のChromiumの実画面・操作試験を維持して最新head SHAでrules/browser両方成功を確認する。
- **体感は未確定**：数値的な滑らかさと、iPhone Safariで「引っ張られない」「景色を気持ちよく見られる」感覚は別。実機試遊が必要。


## 2026-11-02 進行方向カメラ（Issue #96）

- iPhone縦画面（320×568、390×740前後）の右移動：長い道を歩いている間、主人公が左約20〜25%付近に寄り、右側の道が大きく見えること。左は対称、上下は約35/65%の上下寄りを目安とする。横画面844×390は横方向の偏りを弱める。**割合は目標値であり実機の触感に合わせて調整してよい**。
- 短い2マスタップで画面が大きく動かないこと。手動パン→短距離タップでは逆戻りしないこと。追いついたあと長く進めば、実進行方向へ構図が育つ。曲がり角／180度反転／到着／再タップ／停止でも大ジャンプなし。
- 既定巡礼の現地と地図移動、速度5.7/7.35、0.8通常画角・0.46/0.38特別な遠望とReduced Motion、世界端、縦横回転とUIを確認。旧atlas/classic/prototypeは不変。
- Nodeは数理的な追従・境界・フレームレート・速度を検査し、ブラウザは入力と描画の結果を確認。実機Safariでの疲労・誤タップ・揺れはそれとは別に試遊で判断する。


## 2026-10-25：通常屋外の画角を固定する試用（Issue #70）

- 既定 `/`/`?journey=1` の初回と港・茶屋・街道・草原・湖・高地・玻璃都・遺構の歩行中は0.8固定（場所の名前やBGMの地域が変わっても倍率は変えない）。
- 明示された `journey-scenic-wide` 地点だけ0.6、出入りは既存の補間・保持を利用する。屋外にある通常の展望・小景・遺構の接近で1.35／1.8等へ拡大しない。将来の実屋内だけ1.35にできるが、現行は屋内マップ自体を追加しない。

- Node/Chromiumで合格しても、iPhone Safariの目の疲れやタップの感触を確認したことにはならない。試遊で、通常歩行の落ち着きと特殊展望の自然な出入りを確認する。

## CI（GitHub Actions）

- `rules`: Node.js 22で `npm run check`。構文解析と `tests/*.test.mjs` の地形・可達性・カメラ・音楽・会話検証（2026-10-20のmainで65件。検査の追加で増える）。
- `browser`: Chromium + Playwright 1.57.0。明示した旧2世界 `?mode=classic` と既定 `/` のindex.htmlを起動して、読み込み・初期UI・68曲の音楽室・スタート地点近くの小橋をタップして星風回廊へ移動する操作を検査。続けて `?prototype=1` の4施設表示・2地区の地図・森→旧港の徒歩移動・通常版へのリンクを検査。
- CI成功は機械テストの成功のみ。人間の採用判断・独立監査・iPhone実機試遊の代わりにならない。

## iPhone Safari 実機で確かめること

1. 画面開始位置から東約4マスに小橋が見え、タップすると星風回廊へ渡れるか。
2. マップ・会話・場所への徒歩移動、橋の往復、施設の入口で正しく止まるか。
3. カメラが指に対して滑らかか、主人公が画面外に出ないか、停止中も移動中も二本指で倍率が変わらないか。
4. 湖・トンネル・砂漠・草原の見え方と、湖が十分大きいか。
5. BGMをONにして地区切替時の音切れ・ノイズ・足音の大きさを実耳で確認。スピーカー/イヤホン別も有益。
6. 既存GitHub Pages URLが開き、Safariの再訪でも更新が反映されるか。
7. `?prototype=1` で小さな旅を開き、4施設訪問と森→旧港の移動・会話を確認。ヘルプから通常版へ戻り、2世界の橋を維持しているか確認。
8. BGM/SEの設定を変えて再訪し、`tidal-atlas:`の設定保持を確認。ゲーム進行のセーブ機能は未実装。

実測していない項目は**未検証**と記載。シミュレーションだけで「iPhoneで動いた」「音切れゼロ」と表現しない。
