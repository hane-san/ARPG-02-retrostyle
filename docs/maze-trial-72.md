# 南西迷路の歩き方を比べる（#67 / #72）

基準main `68b8f84f40e3d0f31cdb577473d1c459da316f29`。
採用根拠は#67の比較実験の委任。実装前の技術設計・受入条件は#72に記録した。
本番でこの方式を使う採用判断はしていない。

## AとB

- A：既定 `./`。今までどおり、目的地までの合法経路を一度に歩く。
- B：`./?maze=turns`。風蝕迷路の作者指定矩形x14〜44・y98〜123の
  古代床Aにある未訪問の曲がり角で一度止まる。停止した角は歩いた場所になるので、
  同じ行き先を再指定すればその先を歩ける。手引きからA/Bを選べる。
- 地図からの広域徒歩、街道F・通常道・橋、範囲外の遺跡や草原は制限しない。
  旧classic/prototypeはB指定を含めても対象外。画角や画面サイズで規則を変えない。

## 実装の境界と危険度

high（徒歩経路の採用部分と到着処理へ接続）。A*、地形、障害物、歩行速度、
衝突、橋を変更せず、Bだけ既存経路のprefixを採用する。
途中での行き先変更も、既存routeJourneyWalkが返す確定済みの次の1歩を保持する。
短縮した経路では最終目的地の到着処理を外し、遠くの会話・調査・発見を実行しない。
自動再開や最終目的地の予約はなく、次の行き先はプレイヤーが選ぶ。

記憶するのは実際に到達したマスだけで、経路の計画では覚えない。
Setはページ内だけ、新しい保存キーや永続の発見記録はない。
通常フィールドに進捗、停止理由のトースト、方式名などの常設HUDは追加しない。
説明と入口は既存の手引き内だけ。既存の主人公停止タップ、道具、会話遮断、
68曲と選曲、BGM既定OFF/SE既定ON、屋外0.8と特別遠景0.6を維持する。

## 決定論的な比較

`node tests/maze-trial-report.mjs --save`。
同じ地形・開始点・目的地へ、到達するまで同じ目的地を指定し直す例。
歩行速度を変えず、実際のタッチ負担や楽しさの証明とはしない。

| 出発→目的地 | Aの指定/歩数 | Bの指定/歩数 |
|---|---|---|
| (17,102)→(33,118) | 1回 / 32マス | 7回 / 32マス |
| (33,118)→(22,103) | 1回 / 26マス | 7回 / 26マス |

[全停止地点と地形ハッシュ](maze-trial-72-results.json)。
ブラウザの短い比較(17,102)→(21,106)は、Aが1回で到着、
Bが(21,103)で一度止まり2回で到着する。

## 検査

- `tests/journey-maze-trial.test.mjs`：A/地図/街道/範囲外の不変、空・到達不可、
  計画だけでは未訪問のまま、記憶の寿命、実迷路の合法prefix・繰り返し指定の到達、
  歩行途中の再指定を検査。
- `tests/journey-maze-browser.mjs`：320×568/390×844/844×390、A/B各入口から
  実際に地図徒歩で同じ地点へ行き、実タッチで停止・再指定を比較。
  石版への接近が途中で止まった場合、会話・発見が開かないこと、エラーなしを検査。
  検査は既存の地図の主人公マーカーと描画カメラを観測し、本番デバッグAPIを足さない。
- `npm run check` / `npm run test:browser` と正確なSHAのCI結果はPRに記録する。
  途中の検査では、小画面の地図のborder幅をlocator座標へ含めたため1マスずれを観測。
  製品の座標換算は変えず、検査の押下位置をpadding/borderの規約に合わせて修正した。

## 夕方の試遊と限界

昼ランの統合・Pages更新後、同じ場所をA/Bで歩く。Bが突然止まったように感じるか、
角で先を選ぶのが探索に結びつくか、再タップが多すぎないかを比べる。
通常の最短経路計算は残り、直線の先や地図徒歩では未知の土地を通り抜けられる。
視界や分岐の正解を厳密に隠す方式ではない。新たな角が連続する道では手数が増える。
知った角を通れるのはそのページだけで、再読込後は忘れる。これらも比較対象に含める。

iPhone Safari・WebKit・実耳・人間の探索感/負担・独立監査は未検証。
今回の確認は自己確認。#67全体やBの本番採用を完了扱いにせず、試遊結果を次の判断へ渡す。
