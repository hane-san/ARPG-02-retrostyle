# 空の枝道 — 中央から四方へ続く土地（Issue #124）

独立した100枚を歩き比べる実験。固定画面方式の全体採用は未決定。通常世界・旧モード・全110曲・保存名前空間・物語の未確定事項は維持する。2Dの画面単位探索は接続設計の参考であり、他作品の地形・画像・曲を複製しない。

## 採用した構図と寸法

各画面は15×15タイル、タイル32px、10×10枚。長方形化は今回行わない。320縦でも人物と道の寸法を維持し、北端では歩行範囲の外へ空を大きく描く。共通等方倍率は `min(.9,(stageW−24)/480,(stageH−24)/576)`。通常歩行では構図/倍率不動、画面送りは従来の560ms五次補間。縦横別の伸縮はない。

開始は左上を(0,0)として **(4,5)「旅支度の分水庭」**、安全床(7,11)。帰りの道標(7,12)と手引き「元の場所へ戻る」が元の世界へ戻す。旧「空の麓の集落」の道標も残す。新しい道具/クエスト/進行状態は作らない。

|方角|最初に着く土地|曲|旅の見え方|
|---|---|---|---|
|西|二つの橋の水路|42:1|水と橋、温室や森の生活へ|
|北|器を乾かす七段の縁|42:2|同形の乾いた水路から北の空へ|
|東|返事を待つ壁の脇|43:1|石壁と列石、尺度が変わる道へ|
|南|粉袋を数える風車|48:1|畑と風車、花原と山の迂回へ|

既定BGM OFF・SE ON/独立音量を維持。開始曲は38:2「次の人が来るまで」。全38cue割当（37演奏＋静けさ）を維持し、同曲の画面送りでは再始動しない。

## 地形・接続の技術計画と実装

1. `fixed-geography.js`に共有境界を集約。幅だけでなく、辺上の通行帯`bands`、主たる案内の中心、接地素材と両岸の共通色を保持する。両側は同じdescriptorを参照。通常道/広い草地/片寄った峠/水辺の桟道/上下二帯を使い分ける。中心は3/4/5/6/7/10/11、通行マス総数は1/3/5/7/8/9/11。8は7＋1の分割開口。
2. 旧33枚の主要ループを保ち、新67枚の輪郭・道を広い地面/曲がる道へ再構成。全辺を自動開放しない。5接続を追加し全体143接続。中央から北/南、布庭と工房、風車と雲環、便り窓と青屋根を接続する。
3. 白花の裂け野(5,6)と風見石の尾根(6,6)に、世界座標で続く斜めの裂け目を作る。境界の上1〜7、下13が通れ、10は実際の不通地形。上下の岸は隣でも同じ岸。花原の下(7,11)から見えている上(7,4)へは、上側の先端を回る24歩の迂回（A*配列25点）。対岸は貼り付けた絵ではなく歩ける床。地図にも裂け目を描く。
4. 水/乾いた溝/裂け目/建物solid/幹は不変の障害物。設備で地面が分断された時は、既存床を優先する最小掘削で内側の空地だけを結ぶ。水を埋めたり裂け目に橋を生やしたりしない。木は設備・NPC・出入口の3マスの奥行きを避けて置く。全床BFS、全通行帯の実際の往復、全設備/調べ口/NPC/着地を検査する。
5. `gatePoint`/地図ボタン/タップ/地形/案内は同じ境界位置を利用。二帯には双方へ矢印を置く。辺と地名札は44px相当の押しやすさを残し、矢印の近くの普通の地面をタップしただけでは出口へ吸わない。遷移中の入力遮断・安全な一マス内側への着地・古い経路破棄・即時逆戻り防止は従来通り。
6. 隣の地面は通行可能な辺だけでなく、地理的に隣接した画面も描く。見える対岸や段の下が、別の経路で着く地形として続く。描画範囲と既存の地形Canvasを使い、全100枚を毎フレーム描画しない。

## 試遊順

音楽をONにして手引き「空の枝道へ」。

- まず分水庭から西/北/東/南へ一枚ずつ往復する。4方向の地面・幅・音の違いを見る。
- 南の粉袋の風車から東へ白花の裂け野。下の岸から見える上の道へ向かうと、左上を回り込む。隣の風見石へは上の広い開口と下の細い開口の両方から往復できる。
- 分水庭→北の空器→西のガラスに映る池→北の水段→北の受水殿→北の温室→北の段畑。東へ風車→遠原→列石→帝門→閉殿→分水梁。昔からの青屋根の坂へは、温室→南の受水殿→西の水の庭→西の帰り並木→北の橋→東の下り道→北の高庭→西の風道→西の坂。
- 地図の隣接地名も実際の出口まで歩く。見えるだけの崖へタップしても隣には渡らない。帰りは分水庭/旧集落の道標、または手引き。

## 見やすさと操作の手直し（2026-11-09、持ち主の依頼）

コンセプト・地形・接続・曲・倍率（15×15／共通等方倍率／560ms）は変えず、表示と細かな挙動だけを直した。

- **出口の札**：画面上でおよそ13px以上の太字、角丸・縁取りの札に統一。札の位置は `fixedGuideLayout`（`fixed-screens.js`）が一か所で決め、描画とタップ判定（`fixedExitTarget`）が同じ値を使う。帰りの道標と同じマスに出口の札が重なる時は、札を道標の空いている側へ寄せ、道標の名前を反対側に置く。横の札が別の札と触れる時は矢印の上へ回す。札は建物・設備・木より手前に描き、主人公が下にいる時だけ半透明にする（大きな家に西の札が隠れていた港・川の画面を解消）。
- **出口の矢印**：明るい下地つきで地面から読み分けやすくし、道標と同じマスでは一マス縁側へずらす。
- **隣の画面**：見える隣の地面に薄い霞をかけ、今歩ける一枚を先に読めるようにした。画面送りの間は霞を行き先と入れ替える。横長の画面では隣の地面を画面幅まで描き、外側の端は遠景へ溶かす（縦の切れ目を出さない）。
- **行き先の印**：濃い縁＋明るい輪の二重線にして、明るい床でも見えるようにした。
- **中央の分水庭**：開始位置の真横にいた「道具を洗う人」を一マス西（5,11）へ。
- **地図**：最上段の地名が上端で切れないように文字の基準を上揃えに。今いる画面を濃い枠、隣の画面を細い枠で囲み、それ以外を薄く覆う。現在地の印を大きく。行き先ボタンは北→東→南→西の順に矢印付きで並べ、「へ」だけが次の行へ落ちないようにした（読み上げは「北、◯◯へ歩く」）。
- **キーボード**：押し続けた方向は、オートリピートを待たずに次のマスを先に予約して途切れず歩く。歩いている途中で向きを変えると、今のマスを歩き切ってから曲がる（前のマスへ戻ってから曲がり直さない）。画面送り直後に押しっぱなしのキーで逆戻りしない従来の挙動は維持。

追加の決定論テスト：全100枚×4画面サイズで、札の文字が13px以上・盤面内・札どうしと道標名が重ならないこと、ずらした札そのものをタップしても正しい出口になること。物理iPhone/Safari、実耳、独立監査、人間による見た目の受入は未実施。
