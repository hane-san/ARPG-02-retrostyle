# 入口・場所に合う画角・音の連続性（Issue #28 / #30）

2026-10-20の人間の明示依頼により、草原湖を既定入口とし、遠景が映える場所と村で画角を変える5段階の演出を採用。Issue #30の追加依頼で手動倍率を廃止し、下記の画角へ更新した。最新main `2a607eb` の初回徒歩・補間描画修正（#33）を保持する。地形・経路・速度・既存保存名は維持する。

## 入口

| URL | 開く世界 |
| --- | --- |
| `./`、`?journey=1` | 草原と湖（既定） |
| `?mode=classic`、`?journey=0` | 以前の潮環群島と星風回廊 |
| `?prototype=1` | 台場ミニ |

明示 `journey=1` → `prototype=1` → classic指定 → 草原湖、の順で判定する。手引きの「以前の広い世界を歩く」から旧2世界に戻れる。旧2世界の橋・施設・NPC・音楽は継続。タイトル・公開パス・設定名の変更や、進行セーブの追加はない。

## 場所に合う5段階

| 段階 | 目標倍率 | 場所・意図 |
| --- | --- | --- |
| 5 | 0.6 | 草原中心、大湖、塩原、夕景。新しい最遠景 |
| 4 | 0.8 | 普通の街道、草原周縁、峠。これまでの最遠景 |
| 3 | 1.0 | 港、茶屋・小屋の近く。暮らしへ少し寄る |
| 2 | 1.35 | 将来の屋内用。現行マップには屋内がないため未使用 |
| 1 | 1.8 | 将来の最寄りの場面用。現在は未使用 |

番号は近い1→遠い5。5種類の設定を持つが、現在のフィールドで使うのは3/4/5。建物の説明を開いたり人と話しただけでは屋内扱いにしない。新しい屋内マップは今回作らない。

`journey-camera.js` が候補へ1.2秒連続滞在してから採用し、採用した場面は最低5秒保持する。茶屋・小屋は入口から7タイル以内だけ近景、茶屋の地域でも橋や畑は街道。草原の中心（36,38から18タイル以内）が5、周縁が4。地名・音楽の地域と画角の境界は別に保つ。

切替は滑らかに補間し、主人公の画面上の位置・世界境界・人物可視を保つ。静止中の倍率移行も60fps対象（Issue #31）。窓・会話・指操作中は補間を止める。全モードで＋／−を除き、ホイール・二本指による倍率変更も無効。ドラッグ・自分へ・徒歩の途中変更は継続する。旧2世界とミニ版は従来の初期倍率1.25に固定し、新しい場所演出は草原湖だけに適用する。下部道具は地図／音楽／自分へ／手引きの4つ。

## 音の不連続

実際の `scheduleNote` とOfflineAudioContextで、0.5秒までレンダリングしてから1.1秒の停止を予約すると、修正前のpadは**停止前の波形が最大0.00555変わった**。未来のランプ終点の取消しが、まだ鳴っている音の音量カーブまで変えていた。

`audio-envelope.js` で元の線形／指数カーブを保持し、native `cancelAndHoldAtTime` と未対応・例外時の補償の両方で、停止時刻まで同じカーブを復元する。そこから40msで0へ減衰し、振幅0になってから音源を止める。二度目以降の停止を後ろへ延ばさず、短時間の切替で音を復活させない。通常のharp／drumの終端も微小な振幅から0へ落としてから終了する。

修正後はpad／harp／fluteとnative／fallbackの6ケースで、停止前の最大差は浮動小数点誤差の範囲（7.5e-9以下）、終了後は0。既存のClaude版busフェード補助は保持する。68曲・BGM初期OFF・SE設定・足音は継続。

これは再現した停止・切替ノイズの修正であり、iPhoneの実機負荷やデバイス固有の音割れの解消を測定したものではない。実耳・Safariの判断は試遊へ引き継ぐ。

## 操作負荷中のBGM（Issue #30）

ユーザーの追加回答は「BGMがONのときに聞こえる」。メニューを開くだけでは曲は切り替わらない。従来の1.25秒先読みでは、mainスレッドを4.2秒止める実録音検査で約1.1秒の無音を再現した。短い操作時の実機ノイズと同一原因と断定する検査ではない。

選んだ曲だけをOfflineAudioContextで24kHz・ステレオPCMへ合成し、AudioBufferSourceのnativeループで再生する。再生中の発音予約と多数のoscillator処理を画面操作から外す。2周期を合成して後半を切り出し、前周期からの音の余韻もループ境界に含める。4秒分ずつ音源ノードを接続して合成を進め、終了したノードを区間の間に切り離す。曲全体のフィルタを同時に維持する負荷を避け、ノートの準備は32音ごとにUIへ制御を戻す。準備中は現在の曲を維持し、できてから従来の240msフェードで切り替える。

準備は同時1曲、完了キャッシュは最大2曲。途中の古い選択を捨て、OFF・背景化・破棄の後で遅れて完成した音源は鳴らさない。全68曲を事前に保持したり、音源を外部から取得したりしない。OfflineAudioContext非対応・合成失敗の環境は従来の先読み合成に戻るため、同じ負荷耐性は保証しない。Web Audioのユーザー操作アンロック、BGM初期OFF、音量、SE、保存キーを保持する。
